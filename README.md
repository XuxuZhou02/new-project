# Content Systems Portfolio

A portfolio site for the **Lyft · UX Content Design Intern (Summer 2027, Toronto)** application.
It's a single static file (`index.html`) that can be published with GitHub Pages.

## How the three case studies map to the job description

| Case study | Job requirement | Skills shown |
| --- | --- | --- |
| **One concept, every surface** | Information architecture, publishing workflows, "connected content objects" | Content audit, a four-layer content model (Concept → Facts → Variants → Placements), faceted taxonomy, string key naming convention, redesigned publishing workflow, governance, and an interactive demo where one policy change updates every surface |
| **When the ride doesn't go to plan** | UX writing (UI, notifications, errors), brand voice, accessibility | A three-question framework for error copy, tone that shifts with the stakes, six before/after rewrites with automatic character counts, accessibility and French text expansion |
| **Ready for trip one** | Learning experience design, learning center, knowledge base | Learning objectives, sorting topics into "before you drive" vs. "when it happens", a learning path, a micro-lesson storyboard, an interactive knowledge check with feedback, and a link back to the content model from case study 1 |

Each case study also includes its process, decisions and trade-offs, partner and handoff details, and a measurement or evaluation plan. The home page has a "Skills at a glance" table that maps each skill to evidence.

All three case studies use the same rideshare scenario, which shows the "systems mind" the job description asks for.

## What to change before you submit

Search `index.html` for `[` and `TODO`:

- `[Your Name]`, `[program]`, `[university]`, `[Month 2028]`, `[Degree, program]`, and languages
- `[your.email@example.com]` and the LinkedIn link (search for `linkedin.com`)
- The timeline on each case study (`[3 weeks, Fall 2026]` and so on)
- Rewrite the About section with your own background
- Keep only the tools you have actually used in the Tools list
- When you're done, remove `class="ph"` (it highlights the placeholders)

## Make the portfolio more convincing (strongly recommended)

The case studies are self-initiated concept projects, and the page says so. Interviewers will ask about the details, so:

1. **Run a real audit.** Pick an app you use (rideshare or food delivery, for example) and its help center. Screenshot how the same concept is described in different places, and replace the audit table in case study 1.
2. **Run a 5-person comprehension test.** Show five people the before/after messages from case study 2 and ask, "After reading this, what would you do next?" Add the results where the `TODO` comment is.
3. **Talk to 2–3 drivers.** Check the assumptions in case study 3 and add one real quote to the page.
4. **Read every paragraph in your own words.** Make sure you can explain the reasoning behind each decision in an interview.

## Publish with GitHub Pages

1. Merge this branch into `main`.
2. In the repository, go to Settings → Pages. Under Source, choose `Deploy from a branch`, then choose `main` and `/ (root)`.
3. After a few minutes, visit `https://<your-username>.github.io/new-project/`.

## Preview locally

Open `index.html` in a browser. No build step is needed.
